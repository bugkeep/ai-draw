# 子 Agent 的作画步骤与持续记忆

每个绘图输入使用独立的 `drawing_execution_memory` 上下文。它以当前 task、agent、input 和 run 为范围，从已有 SQLite 记录恢复最近成功操作和已经送达的评审比较。它不执行绘图、不写入数据库，也不代替当前图片与原始任务。

模型通过既有 `compact_context` 工具保存自己的作画步骤，使用原有工作记忆表与检索接口。工具定义、存储结构和模型连接保持不变。`saved_step` 提供当前记忆版本、原始检索编号和本输入标记；`created_in_current_input` 根据 SQLite 中实际成功调用的归属核实笔记来源。模型写入的标签用于表达步骤范围，调用记录决定笔记是否属于当前输入。

## 具体步骤的内容

持续作画需要记录以下内容：

| 字段 | 内容 |
| --- | --- |
| target | 当前形体或连接、实际对象编号或图片区域 |
| evidence | 已查看的参考、共同布局、标志点，明确画面左右和人物侧别 |
| structure | 形体大小、连接位置、遮挡方向，以及可见轮廓的终点与重现位置 |
| method | 下一次原生操作、当前对象或有依据的锚点、轮廓起止与遮挡断点；独立笔画使用独立 path |
| protect | 需要保留的已有结构、亮部、开口和相邻连接 |
| visible_check | 修改后在当前特写及全图中应该看见的具体变化 |

模型在 `summary` 保存当前步骤，使用 `completed` 记录经过核查的进展，使用 `pending` 保留本输入尚未完成的事项。方法失败或步骤得到验证时更新笔记，普通工具调用不需要重复保存相同计划。替换笔记时继续保留有效约束与后续工作。只修改属性的任务继续保留其他属性，研究任务按照原要求返回研究结果。

`object_ids` 使用当前原生对象编号，`evidence_refs` 使用工具回执中的 `memory_` 检索编号。图片查看编号、参考图编号、Agent 编号与结果编号分别属于各自的接口，不写入 `evidence_refs`。没有相应记忆回执时可以省略该字段。

当前步骤建立一个有明确比例、连接和可见结果的构造单元；参数已知的相关构件可以批量完成，也可以建立整个阶段的大形。其余要求继续待办。`next_step_focus` 将本轮评审的首个发现作为需要核查的焦点，列出当前区域、现有对象及已删除对象；它不会覆盖共同构图。`work_phase` 显示最后成功操作、是否刚执行清理，以及当前准备状态中已经送达的读取次数。需要重建的任务在清理后继续建立正确结构；明确要求擦除的任务继续保留原范围。

## 根据实际操作继续

最近操作摘要提供原始 `memory_ref`、调用编号、工具名称及仍存在或已经删除的对象编号。移动操作列出实际执行的 `dx/dy` 和对象在全部已执行操作之后的当前范围。笔画摘要还提供独立 path 数量、示例路径的连续点数、实际 `smooth` 设置、坐标单位、跨度、线宽和透明度。跨度使用调用原有的坐标单位；归一化图片单位与画布单位分别解释。

闭合和填充状态一同列出。`reshape_path` 未提供的样式标记为 `inherit_current_object`，需要从当前原生对象理解，不填入创建新笔画的默认样式。只读摘要不改变原生样式继承或绘图执行。

`current_filled_objects` 从当前私有草稿恢复填充形体的编号、名称、原生范围、角度、填充、透明度及数组中的前后位置。检查遮挡问题时，先判断已有形体是否被前方填充遮住，再选择调整图层或修改轮廓。该索引不声称每个填充都造成错误，也不授权修改用户没有要求改变的图层关系。内容优先展示当前目标与前方填充，其余对象仍通过原有工具检索。

一个 path 的点列连接成一条连续笔画。将它命名为短排线不会产生抬笔；多个短排线需要多个独立 path。实际笔画、图片与任务要求共同决定绘法是否有效。工具成功、对象命名或动作数量都不作为画面完成的依据。

`current_object_index` 提供当前原生对象编号、名称、类型、原生范围、角度和版本，支持具体修正、选择和报告绑定。共同构图中的计划坐标与修改后的对象坐标分别标识。最多 120 个对象的场景展示完整索引；较大场景展示当前目标及最近操作中的现有对象，其他内容通过既有检索获取。该展示数量只控制上下文长度。前一输入的报告传递当前仍存在的形体绑定，完整原始报告保留在 SQLite。

索引同时保存原生颜色、填充、线宽、透明度、线型、roughness 和字体属性，以当前索引中的 `style_id` 引用相同样式。持续笔记保存实际样式属性；这些索引编号只属于当前上下文。场景前缀中能够由索引逐字段完整还原的重复元数据改为编号引用。完整几何、额外字段、工具返回和错误消息继续保留原值。

简短路径提供 `current_polyline`：复用现有 `recall_path_geometry`，给出最多一画布单位简化误差的当前中心线样本，包含当前平移和旋转。它帮助核查端点、连接与透视关系；这些样本不代表原始曲线控制点，也不证明笔画在填充遮挡后仍然可见。较长曲线通过原有 `recall_memory` 获取。该过程只读当前草稿，完整原生几何保持原样。

独立草稿评审在候选报告、已有修复后的整幅查看请求，以及停滞、错误恢复检查点执行。`view_canvas` 不带区域表示整幅查看；区域查看用于观察局部，修改后附带的当前全图与特写继续提供。构造修改和实际擦除纠正后都可以明确请求整幅复核；仅删除旧对象、尚未建立所需形体的中间状态继续重建。擦除重复或错误线段已经满足要求时，可以复核和返回候选报告，不要求添加替代笔画。

候选评审为普通 `repair` 且报告没有明确未解决事项时，在同一 input/run 中继续修改，保留已执行动作与工作笔记。原有独立比较判定实际纠正为 `ineffective` 或 `regressed`，并生成 `ineffective_repair` 时，runtime 直接交回 `source=independent_draft_comparison` 的未获批准候选，携带完整评审、失败方法与现有编号。这条交接使用已有结果机制，不生成子 Agent 自述的 DrawSpec 报告，也不需要额外模型调用。主 Agent 读取完整评审、草稿提案与原有 `next_strategy`，通过新输入调整范围、参考或构造方法；同一子 Agent 保留上下文和待提交的原生动作。该交接保持 `blocked`，不代表作品完成，也不依据次数或耗时触发。当前场景、输入、选择和未读错误的校验继续使用原有实现。

报告通过 `unresolved` 或未解决的检查明确说明前提缺失、约束冲突等事项时，也由主 Agent 调整输入。普通未完成作画继续执行，后续计划阶段写入报告摘要。画面发生变化后，上一评审的未处理事项继续携带，明确标为较早画面的发现，结合当前坐标和图片逐项核查；已经解决的事项继续向前推进。阶段通过后交给主 Agent，整幅评审继续执行。具体调用与耗时证据见[子 Agent 作画调用与耗时检查](child-loop-latency.md)。

评审历史明确区分观察结果与建议方法。当前完整评审和工具错误继续出现在原上下文中；摘要只帮助模型回忆前面的尝试。模型需要将对象归属与建议绘法同当前图片、真实编号和共同构图核对，说明实际缺失的构造前提。

## 把美术指导转成实际步骤

原始 DrawSpec 完整保留。`art_execution` 将该输入的媒介、焦点、明暗设计、形体范围、当前阶段与后续阶段集中说明，并提供当前阶段的绘制顺序：

| 阶段 | 实际工作 |
| --- | --- |
| block_in | 建立整幅剪影、动态、主要明暗形体；核对比例、留白、连接和前后关系，记录临时辅助线编号 |
| contour | 根据体积建立实际可见轮廓，明确起点、转折、终点和遮挡区间；保留连接与开口，逐步替换辅助线 |
| modeling | 按原定光照组织亮部、中间调、阴影和接触投影；主要明暗形体成立后使用有方向的排线 |
| detail | 选择表现视觉重点的特征与材质，简化次要纹理，整理连接、遮挡、轮廓终点与剩余辅助线 |

包围范围和 ovoid、box、cylinder 等构造体积用于定位；最终轮廓表现具体对象的形状。已有正确轮廓优先保留，需要调整线宽等属性时原位修改；清理依据当前图片，不按对象名称批量删除。

已知当前原生几何或共同构图标志点时，直接使用画布坐标完成连接；需要从图片读取新锚点时使用该图片的坐标映射。原始创作和明确的遮挡修正可以通过闭合、纸色填充的前景剪影与图层顺序，让背景线条在遮挡处自然消失，前景内部细节继续位于填充上方。明暗形体、相邻表面的区分和连续留白需要在纹理前建立，具体绘法服从原有媒介与 art direction。精确编辑仍然保留未要求改变的属性及前后顺序。

作画步骤同时考虑视觉重点、内容表达、形式统一、细节取舍和连贯的表现方式。它们通过原请求与 art direction 决定轮廓节奏、明暗、空间和细节；精确属性编辑与研究输入保留原范围，diagram 输入继续使用原有指导。

具有灭点的建筑构图还提供原有顶点、接触标志点沿灭点投影的数值参考。它们只作为构造依据，不自动增加任何绘图动作。评审的几何判断需要与当前轮廓、图片及原有标志点共同核查，不能把修复建议当成已证实的空间事实。

## 恢复与隔离

上下文只读取本输入的操作和评审，校验 run、input、agent 和 task 的对应关系。其他子 Agent、其他画布以及同一子 Agent 的其他输入不会混入本输入的执行记录。原有工作笔记仍按既有规则传递；成功保存调用不属于当前输入的笔记作为历史资料，在复用前核查当前草稿。

上下文压缩或进程重启后，执行记录继续从 SQLite 恢复。当前对象存在性以当前草稿为准，已经删除的编号单独列出。展示最近三次操作与比较只控制上下文长度，原始日志继续保留，没有增加作画动作、轮次或时间限制。

## 检查

运行 `python -m pytest tests/test_child_drawing_memory.py tests/test_child_art_context.py`，检查真实原生对象和 SQLite 下的持久恢复、输入与画布隔离、删除对象标记、完整错误保留、样式与场景元数据还原、移动旋转后的当前路径，以及已送达评审的范围。该检查不调用模型，也不生成模拟模型回复；它不能证明绘画质量。

真实绘图继续使用冻结的模型配置、主 Agent 的其他角色提示与派发协议、工具和独立评审。主 Agent 完成判定及对应提示按用户单独授权读取原计划和未完成事项，具体边界见[子 Agent 美术上下文与真实作画记录](child-art-quality.md)。每轮保存完整上下文及实际回复，核对模型是否保存并使用步骤、是否改变失败的几何方法，以及修改后的画面是否满足原要求。局部改善和完整作品通过分别记录。

当前对象的重复字段、原始标准引用、末尾图片依据与报告格式的表达见[子 Agent 上下文中的重复信息压缩](child-context-projection.md)。这些处理保留完整原始任务、当前几何、图片及错误；通过真实输入重放核查字段还原，作画效果仍由原有验收与实际成图分别判断。

擦除未产生修改时的当前路径观察，见[子 Agent 的原生擦除定位](child-eraser-targeting.md)。这些信息只补充子 Agent 的执行记忆；实际绘图、擦除、坐标转换和独立评审继续使用现有实现。
