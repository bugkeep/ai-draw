## 子 Agent 的执行规则

每轮继续提供实际当前全图、已有特写和参考图片。已知参数的相关构件可以批量建立；清理后继续同一个构造步骤。原生几何工具、逐路径 `smooth=false`、有意使用的曲线，以及遮罩和前景的绘制顺序均明确说明。

独立草稿评审在候选报告、已有修复的明确整幅查看请求，以及原有停滞、错误恢复检查点执行。明确查看请求需要在上一已送达修复评审之后完成可见纠正，包含实际 `erase_strokes` 修改。删除旧对象后仍缺少所需形体时继续建立结构，区域查看用于局部观察；擦除重复或错误线段本身已经完成纠正时，可以请求整幅复核，无需添加替代笔画。普通绘图修改继续获得新图片，完整评审使用原有实现、提示和评分。候选报告获得普通 `repair` 时，子 Agent 在原 input/run 中继续绘画，保留笔记与已执行动作；真实比较判定纠正无效并形成 `ineffective_repair` 时，通过未获批准的报告交给主 Agent 调整输入，保留同一子 Agent 和草稿。`ready`、实际前提缺失的 `blocked` 和请求错误继续按现有交接结果处理。最终提交继续使用现有执行机制，整幅结束增加用户授权的计划完成核查，原有图片评审条件保持原样。

当前私有草稿提供原生对象编号、坐标范围、角度和版本；移动记录提供实际执行的位移，明确区分原构图的计划位置和修改后的当前位置。大场景展示当前目标，其余内容通过既有检索获取。前一输入的形体绑定只携带当前仍存在的对象，原始报告继续在 SQLite 保存。较早评审的待办继续携带并标为历史，结合当前图片核查，避免修正一个形体时遗失其他阶段要求。笔记来源通过 SQLite 中成功 `compact_context` 调用的归属核实。对象名称和绑定均不作为可见质量的证明。

没有新增时间、动作或轮次限制。全部工具错误、评审错误、模型截断信息和现有检索能力继续保留。

## 复现

使用独立数据库和原有模型配置，通过 `scripts.inspect_agent_contexts` 捕获运行，再运行原有 `scripts.evaluate_quality --cases street-cafe`。不要向实际用户数据库写入评测任务。以自然完成的整幅结果比较耗时，并同时检查原有结构条件、最终共享图片查看和独立整幅评审；未完成或取消的运行不能作为更快完成的证据。
