# DrawSpec/1：绘图 Agent 通信 DSL

DrawSpec 用美术构图与造型概念表达共同作画计划，使用 JSON 作为语法，使用 Pydantic 校验。定义在 `studio/drawing_dsl.py`；现有 `spawn_agent`、`send_input` 接受 `drawspec` 参数，`wait_agent` 返回相应输入的结构化结果。主 Agent 负责通信、构图版本和共享画布提交。子 Agent 保留独立上下文、私有草稿和原有身份。

## 构图词汇

| 字段 | 美术含义与职责 |
| --- | --- |
| `art_direction` | 媒介、表现方式、视觉中心、线条处理、明暗策略及整幅作品的完成要求。 |
| `frame`、`coordinate_space` | 统一取景范围。构图中的全部位置使用 Excalidraw 原生画布坐标，`coordinate_space` 固定为 `canvas`。 |
| `subjects` | 主体、陪体与环境，记录题材分类及整体范围。 |
| `forms` | 主要形体：卵形体、方体、圆柱体、平面、带状体与形体块面。人物可以表示头颅、胸廓、骨盆和四肢，动物可以表示头部、躯干、肢体和尾巴。 |
| `gestures.line_of_action` | 动态线：表达姿态、重心运动或整体走势。人物与动物需要明确动态线和结构标志点。 |
| `landmarks` | 归属到具体形体的关节、接触点、顶点、中心、特征点或交点。 |
| `proportions` | 按主体或主要形体的宽度、高度测量相对比例。记录比例值、容差及造型依据，不设置通用人物比例。 |
| `relations` | 连接、支撑、前后遮挡、轮廓连续或位置呼应。连接关系引用两个具体标志点。 |
| `negative_spaces` | 主体之间有构图意义的负形与留白区域。 |
| `perspective` | 正投影、一点、两点、三点、空气透视或自由处理；适用时记录地平线和消失点。 |
| `value_groups` | 以形体为单位安排明暗分组，`0` 为黑色、`1` 为纸白。线稿仍需要处理正确的前后遮挡。 |
| `stages` | 根据媒介和要求安排整幅画的阶段及可见完成条件。阶段顺序属于共同构图。 |

`block_in` 表示整体起形，建立动态、主要形体、比例和连接。`contour` 完善轮廓与遮挡。`modeling` 通过体面、光影、排线塑造体积。`detail` 完成必要的特征、材质与边缘处理。根据题材选择所需阶段：线稿可以省略明暗塑造；需要完成的素描必须保留相应的体积与明暗要求。

构图校验检查唯一编号、归属、坐标范围、形体层级循环、遮挡循环、比例自洽与计划接触点之间的距离。例如，`head.width / torso.width` 必须处于所声明的 `ratio ± tolerance`；`supported_by` 两端标志点之间的距离不能超过 `max_gap`。关节与接触点应位于归属形体的范围内。数值冲突在派发前一起返回，包含关系编号、两端坐标、实际间距和允许间距。这些检查针对计划的内部一致性，原生图形是否真正形成正确的人体、空间和笔触仍由实际图片与独立评审检验。

## 派单与版本

首次派单传入完整 `drawspec.composition`。运行时生成内容摘要 `composition_<sha256>`，把完整快照和局部目标保存到既有 SQLite `agent_inputs.message`，作为 `protocol=drawspec/1`、`kind=assignment` 的消息。当前输入的快照保持固定。

后续任务直接引用保存的构图，示例中的编号均由实际运行返回：

```json
{
  "agent_id": "<实际 agent_id>",
  "message": "修正肩部到手腕的轮廓连续性，保留头部和背景。",
  "relevant_ids": ["<实际原生对象 ID>"],
  "drawspec": {
    "protocol": "drawspec/1",
    "composition_ref": "<shared_drawspec.composition_id>",
    "stage_id": "<已声明的轮廓阶段 ID>",
    "intent": "repair",
    "form_ids": ["upper_arm", "forearm"],
    "success_criteria": ["肩、肘、腕连接连续，消除重复轮廓，保留既定姿态"]
  }
}
```

`intent` 可取 `execute`、`repair`、`edit` 或 `research`。`stage_id` 引用已有阶段；`form_ids` 进一步选择该阶段中的形体，空数组使用整个阶段的范围。阶段条件和本次输入的条件同时生效。进入 DrawSpec 的任务不能在后续消息中省略协议；普通历史输入继续支持关闭、恢复和回放。

同一 `revision` 必须对应相同内容。调整共同构图前，处理当前运行输入与待提交结果，再提高版本号。不同画布之间不能解析构图引用；恢复后的旧构图结果不能覆盖当前版本。Running 子 Agent 收到输入后按到达顺序排队；`send_input` 的成功表示接收，当前输入完成后才处理新输入。

尚未通过校验的首次构图会随工具调用原文保存在 SQLite，错误结果带有 `drawspec_draft_call_id`。主 Agent 可以通过同一个派单工具发送 `drawspec.amend`，包含该 `source_call_id` 和需要修正的完整条目，例如两条接触点记录；运行时复用其余条目，再对整份构图重新校验。修正按条目 ID 替换或新增，`remove_ids` 明确删除已有条目；不会修改原始调用记录，也不会自动修正或忽略错误。草案引用限定当前任务中已失败且携带完整构图的主 Agent 调用，不能引用其他任务或已经成功发布的派单。正式构图的后续消息继续使用 `composition_ref`。这使小范围错误无需重新生成整份构图。

第一个执行阶段覆盖整幅画的起形。后续执行阶段需要已提交起形；尚未提交的起形可以通过同一 Agent 的 `intent=repair` 继续完善，无需先提交错误图形。用户对已有作品的局部修改使用 `intent=edit`，保留无关内容。

## 子 Agent 回报

子 Agent 使用工具继续作画；无工具调用时，`content` 返回如下 JSON：

```json
{
  "protocol": "drawspec/1",
  "kind": "report",
  "summary": "前臂轮廓已修正，腕部接触仍需处理。",
  "bindings": [
    {"form_id": "forearm", "object_ids": ["<当前私有草稿中实际存在的对象 ID>"]}
  ],
  "checks": [
    {"constraint_id": "wrist_join", "status": "unresolved", "evidence": "腕部与手掌仍有可见间隙"}
  ],
  "unresolved": ["处理腕部与手掌的连接"]
}
```

`bindings` 建立美术形体与可编辑原生对象的对应关系。运行时拒绝不存在的原生编号、未声明的形体或检查编号，以及缺失应处理形体却没有说明未完成工作的回报。`checks` 的状态为 `addressed`、`unresolved` 或 `unchanged`，其内容始终作为作者自述，不能代表通过验收。

运行时附加实际的 Agent、任务、输入、执行、构图版本与绘图结果编号，计算本次修改的原生对象，并关联当前私有草稿的图片证据及独立评审编号。主 Agent 通过正常工具结果读取这个 JSON，预览后决定提交或继续派单。完整报告保存在 SQLite 的既有完成记录中，参数、几何、图片和长日志按需检索。

协议格式错误完整返回当前子 Agent 的下一轮上下文；输入保持未完成，已准备动作继续保存。无工具调用表示子 Agent 提交本次输入的候选回报，整幅画仍由主 Agent 根据最初目标和独立图片评审决定是否完成。

## 连续修正与上下文

绘图没有总工具次数、总笔画数或固定请求时长上限。分页和记忆压缩控制单条上下文的体积，完整几何与日志仍保存在 SQLite。构图快照、当前阶段、重要对象、未处理工作、当前图片和工具错误保持可用。

局部评审判定一次修正无效时，子 Agent 会获得原评审、原缺陷与新的修正策略，绘图工具保持开放。它可以擦除、替换或重新塑造轮廓后继续检查。实际缺少前置条件、构图相互冲突或提交局部候选时，明确报告未完成事项，由主 Agent 使用现有输入工具继续安排。

模型供应商仍有单条输出容量。实际 `finish_reason=length` 会产生 `model_output_truncated` 反馈，附带实际输出 token 用量和可用的构图草案编号，要求使用较小且完整的调用继续。截断的空工具回复不能结束主任务或子输入；工具参数错误照常完整返回，已经成功的动作保留。该处理没有改变模型、连接配置或增加总轮数限制。

构图中的坐标不能直接标记为 `image_normalized`。使用计划坐标绘制时，省略图片编号和图片坐标模式；根据当前实际 PNG 修改时，使用其最新 `observation_id` 与 `image_normalized`。每次画面变化后，使用自动提供的新图片。

子 Agent 的当前图片还会附带 `drawspec_coordinate_guide`：运行时根据该输入的真实 PNG 范围，把当前任务涉及的计划标志点和形体范围换算成对应图片的归一化坐标，保留同一标志点的画布坐标供选择。局部图有独立的换算结果，图片外的目标只标记为需要画布坐标或其他视图，不作裁切或猜测。指南绑定构图版本、当前草稿内容和实际图片编号；其他输入、旧画面和候选结果图片不能用于这次换算。转换不增加模型请求，也不改变绘图工具。

## 工程边界与验收

DrawSpec 属于独立的受控架构变更，涉及主 Agent 构图、派单、子 Agent 回报与状态校验。自动 RSI 的可修改范围继续限于绘图子 Agent harness；主 Agent、协议、工具、存储、模型和评审均不因此自动放开。独立草稿评审与整幅图片验收的提示、解析、评分和通过条件保持原样。

协议检查、真实存储和原生执行测试可以证明状态与数据正确；作画质量需要分别记录人物、动物、山水和结构图的实际成图、连续编辑、全图检查及延迟。工具成功、对象数量、局部 `ready` 或 DSL 结构完整，都不能单独证明美术质量改善。
