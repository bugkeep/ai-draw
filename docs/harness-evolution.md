# Harness 有界自我改进边界

自动改进循环的唯一修改对象是 harness。其他层以确定的基线版本冻结，评分提高不能抵消越界修改。当前文档记录项目约束；外层自动候选生成与版本晋级尚未实现。

## 可演进职责

Harness 管理模型如何完成任务：主 Agent 与子 Agent 的角色提示、上下文组装与压缩、记忆检索策略、任务分配、观察时机、结果审阅调度，以及错误修正和重新规划策略。绘画子 Agent 继续使用独立会话和私有草稿，主 Agent 负责共享画布提交。原生工具参数、状态和对象归属检查保持既定接口。

内层草稿反馈属于作画过程，用于指导下一次修正；外层验收评审负责判断候选版本的表现，其模型提示、数据集和评分规则冻结。候选版本通过自己的完成检查，仍需接受外层独立验收。

## 冻结职责

| 部分 | 冻结内容 |
| --- | --- |
| 评估层 | 任务集与留出集、评分提示、检查实现、结果解析、视觉验收条件 |
| 改进器 | 改动生成流程、可修改范围和实验预算 |
| 版本选择器 | 晋级与拒绝规则、基线管理、实验归档 |
| 模型与连接 | 模型版本、连接参数、凭据配置、限流与重试基础设施 |
| 编辑器与 API | Excalidraw 集成、前端交互、网络路由、导出与事件协议 |
| 绘图执行 | 原生对象格式、工具接口、几何计算、擦除、渲染、版本检查与提交事务 |
| 存储 | SQLite 结构、任务与会话隔离、工具记录、图片和撤销重做 |
| 工程配置 | 依赖与锁文件、CI、构建及 GitHub 发布规则 |

外层控制系统通过常规工程开发建立和维护，其实现不进入自动候选的修改范围。模型、评测数据或其他冻结部分需要更新时，建立新的实验基线并重新运行基线评测，不能混入某次 harness 候选中。

## 文件边界与验证要求

当前 `studio/agents.py`、`studio/runtime.py` 等文件同时包含 harness 和工具执行职责。不能整目录或整文件放行这些混合职责；自动修改前，应将可演进逻辑移到独立模块，固定其对外接口。`studio/quality.py` 中的完成检查也不能直接充当可被候选修改的外层评分器。

每次实验关联基线 commit、harness 源文件哈希、冻结文件清单与哈希、数据集版本、评审配置和模型配置摘要。控制器在候选运行前后独立核验：仅白名单内的 harness 源文件可以改变；冻结文件、依赖、配置及测试均需与基线一致；新增、删除、重命名和文件链接都纳入检查。候选不得通过启动脚本、导入替换或进程内修改改变冻结组件的行为。

每个候选在独立工作目录与测试数据库中运行，不访问用户作品数据库。完整实验记录、图片和工具日志按所属实验保存；改进器按需检索证据，不把全部执行记录加入模型上下文。

外层实验预算控制候选数量和评测消耗。用户绘图任务继续保持长期、连续作画能力，不增加总工具调用次数或固定请求超时。未完成的评测样本保留状态并明确记录为未完成。
