# 子 Agent harness 有界自我改进边界

自动改进循环的唯一修改对象收紧为**绘图子 Agent 的执行 harness**。主 Agent 及其他层以确定的基线版本冻结，评分提高不能抵消越界修改。当前文档记录项目约束；外层自动候选生成、自动边界校验与版本晋级尚未实现。

2026-10-20 起，以 `9ab01ff717e4705bd8cd4bdad8406cc8ebacbc13` 作为本轮冻结基线。后续候选只改进子 Agent 接到一条输入之后，如何理解该输入、组织私有上下文、观察、使用既有工具和修正草稿。当前未证明整幅画收益的主 Agent 分工提示候选已经归档，未进入这个基线。

用户要求的 [DrawSpec/1 通信协议](drawspec.md) 通过受控工程变更维护主 Agent 构图、派单与子 Agent 回报；该开发单独记录源文件、状态测试和真实绘图，不作为自动候选越界的许可。后续自动实验需要以当时的完整实现重新记录冻结快照，不能把已变化的主 Agent 与旧基线混合比较。状态测试通过或协议功能可用均不代表子 Agent 已经通过美术质量晋级。

用户要求的输出截断恢复同样通过受控工程变更维护：`continue_agent`、待继续事件、主 Agent 通知和恢复事务属于生命周期基础设施。自动候选继续保持这些接口、身份、信号幂等及存储行为不变；输出恢复测试不作为绘图质量评分或版本晋级依据。

## 版本演进与替换

`A₀ → A₁ → A₂` 表示可独立运行的子 Agent harness 版本演进。自我改进可以在该范围内新增、删除、合并、压缩、重写、移动或替换实现。新版本通过验收后替换当前版本；过时模块、重复策略和无用调用路径可以删除。主 Agent 与外部接口保持冻结基线的行为。

正式运行只加载选定的一个版本。运行 `A₂` 不需要启动 `A₀` 或 `A₁`，也不要求保留其运行时代码、包裹层或进程。历史版本通过 Git 和实验记录保存，供复现及版本恢复使用。评测可以分别运行当前基线和候选；历史任务数据可以复用，执行这些任务不依赖历史版本同时运行。

冻结的对外接口、验收标准与评分规则继续有效。外层验收应通过稳定接口检查行为，不能要求候选保留某个内部模块路径、压缩算法或已被替换的实现。版本比较同时记录实际调用路径、模型请求与上下文消耗、首次出笔和完成耗时，清理实现应接受同样的质量与稳定性验收。

子 Agent harness 自有的实现单元测试随该版本一起维护，可以伴随被替换模块增删或重写；固定行为验收测试、留出任务、评审提示与评分实现继续冻结。控制器在实验开始前固定这两类文件的归属和清单，候选不能自行把验收测试改标为内部测试。删除旧模块不需要保留只为旧内部导入路径服务的兼容层，也不能以删除自身单元测试作为功能或质量达标的证据。

## 可演进职责

允许演进的职责限于：

- 子 Agent 的角色提示与对当前输入的局部作画计划。
- 子 Agent 私有上下文的组装、成功工具记录压缩与按需记忆检索策略。
- 子 Agent 对既有全图、局部图和参考图的观察时机，以及既有工具的选择和调用组织。
- 子 Agent 根据冻结草稿评审的实际反馈进行局部修正、保留未解决事项并返回结构化结果的策略。

每条输入的目标、约束、可编辑对象和共同布局由冻结的主 Agent 提供。子 Agent 保持独立会话和私有草稿，只准备原生动作与结果；主 Agent 继续负责共享画布提交。工具权限、参数校验、图片交付凭据、对象归属、关闭恢复和输入队列语义均保持基线行为。子 Agent 仍不能创建或控制其他 Agent。

内层草稿反馈用于指导下一次修正，其评审提示、解析与通过条件也冻结。候选可调整何时利用既有观察和反馈，不能修改评审结论或降低通过条件。外层验收独立判断候选版本的表现，其模型提示、数据集和评分规则保持冻结。

## 冻结职责

| 部分 | 冻结内容 |
| --- | --- |
| 主 Agent | 角色提示、工具描述、上下文与记忆策略、任务拆分与派发、子 Agent 生命周期管理、结果预览与共享画布提交、整幅画完成循环 |
| Agent 基础设施 | 身份与输入编号、顺序队列与并发语义、关闭恢复、调用幂等、任务归属和主子权限边界 |
| 评估层 | 任务集与留出集、评分提示、检查实现、结果解析、视觉验收条件 |
| 改进器 | 改动生成流程、可修改范围和实验预算 |
| 版本选择器 | 晋级与拒绝规则、基线管理、实验归档 |
| 模型与连接 | 模型版本、连接参数、凭据配置、限流与重试基础设施 |
| 编辑器与 API | Excalidraw 集成、前端交互、网络路由、导出与事件协议 |
| 绘图执行 | 原生对象格式、工具接口、几何计算、擦除、渲染、版本检查与提交事务 |
| 存储 | SQLite 结构、任务与会话隔离、工具记录、图片和撤销重做 |
| 工程配置 | 依赖与锁文件、CI、构建及 GitHub 发布规则 |

外层控制系统通过常规工程开发建立和维护，其实现不进入自动候选的修改范围。模型、评测数据或其他冻结部分需要更新时，建立新的实验基线并重新运行基线评测，不能混入某次 harness 候选中。

## 文件边界与验证要求

当前 `studio/prompts.py` 同时定义主子 Agent 提示；仅子 Agent 角色策略可作为候选，`MAIN_SYSTEM` 与主 Agent 工具描述保持不变。`studio/agents.py`、`studio/agent_manager.py`、`studio/memory.py` 等文件也混合了主子上下文、生命周期和工具执行职责，不能整目录或整文件放行。自动修改前，应把可演进的子 Agent 策略移到独立模块并固定接口；这是受控工程整理，需要独立验证主 Agent 和基础设施行为保持不变，不能由候选自行扩大白名单。`studio/quality.py` 与 `studio/draft_review.py` 的评审实现保持冻结。

每次实验关联基线 commit、harness 源文件哈希、冻结文件清单与哈希、数据集版本、评审配置和模型配置摘要。控制器在候选运行前后独立核验：仅白名单内的 harness 实现及其自有实现测试可以改变；冻结文件、依赖、配置及固定验收测试均需与基线一致；新增、删除、重命名和文件链接都纳入检查。候选不得通过启动脚本、导入替换或进程内修改改变冻结组件的行为。

每个候选在独立工作目录与测试数据库中运行，不访问用户作品数据库。完整实验记录、图片和工具日志按所属实验保存；改进器按需检索证据，不把全部执行记录加入模型上下文。

## 先验证局部收益

优先从真实任务记录中固定一组子 Agent 输入、初始原生草稿、参考图、对象权限和布局。基线与候选接收同样的输入和像素证据，先分别验证单个部位或连接关系的修复，再通过冻结主 Agent 做整幅画回归。第一批输入应覆盖人物结构、动物遮挡与山水部件，避免只针对一幅画调提示。

每次先改变一个策略变量。候选必须保持工具校验、对象保留、错误反馈与隔离要求；比较独立评审通过率、可见质量、请求与上下文消耗，以及**完成验收的输入**的耗时。首次画布反馈另行记录。减少调用但未完成任务、提前返回 `blocked`，或只是更快出现草图，都不能计作作画成功或完成耗时改善。未测得稳定收益时保留基线并归档候选。

主 Agent 给出的冲突约束、源图结构不可辨认或冻结工具缺少所需能力，作为外部阻塞单独归因。子 Agent 保留实际错误与未解决事项，交回主 Agent；外层改进器不能把这些阻塞当成修改主 Agent、工具或评审标准的理由。收紧范围提高归因和复现能力，本身不构成质量收益的证明。

外层实验预算控制候选数量和评测消耗。用户绘图任务继续保持长期、连续作画能力，不增加总工具调用次数或固定请求超时。未完成的评测样本保留状态并明确记录为未完成。
