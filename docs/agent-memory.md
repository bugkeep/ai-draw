# Agent 记忆与工具压缩

连续绘图需要保留用户目标和对象身份，同时控制每次模型请求中携带的内容。`studio/memory.py` 使用确定性摘要、SQLite 检索及 Agent 主动保存的结构化工作记忆；这些处理不额外请求模型。

## 工具

主 Agent 与子 Agent 均可使用三个工具，各自只能读取本画布及本人范围内的记录。

| 工具 | 主要参数 | 返回与用途 |
| --- | --- | --- |
| `search_memory` | `query`、`object_ids`、`offset`、`limit` | 当前画布或草稿中的对象信息，以及历史调用、对话、工作说明的 `memory_ref` |
| `recall_memory` | `element_id`、`point_offset`、`point_limit` | 当前原生对象属性及一页路径点；返回总点数与下一页位置 |
| `recall_memory` | `memory_ref`、`section`、`offset`、`max_chars` | 已保存摘要，或完整参数、工具返回及工作说明的 JSON 文本页 |
| `compact_context` | `expected_revision`、`goal`、`summary`、`constraints`、`completed`、`pending`、`object_ids`、`evidence_refs` | 保存新的工作记忆版本并压缩此前工具对话 |

检索每页默认八条，最多二十条。原生路径每页默认 128 个点，最多 256 个点；历史原文每页默认 4,000 字符，最多 12,000 字符。返回的下一页位置可以持续使用，分页数量不限制可取回的记录总量或作品规模。

当前对象取回保留原生属性、样式、名称、自定义数据、旋转角度和该页对应的压力值。历史参数或返回保持原始文本；需要恢复完整 JSON 时，应按顺序读取所有页。检索结果与历史说明不能代替当前几何，编辑前应按 `element_id` 取回现有对象。

例如，用户要求修改较早绘制的眼睛，Agent 可以搜索“左眼”，取得编号，再读取当前属性和所需路径点，使用 `reshape_path` 或其他原生工具修改同一对象。需要大量几何计算时，主 Agent 可把目标编号与具体问题交给子 Agent，并审阅其结果摘要后提交。

## 上下文内容

成功工具结果超过 5,000 字符时使用摘要；`inspect_scene` 始终提供摘要。摘要保留对象编号、名称、位置、尺寸、主要样式和点数，较长数组提供数量与部分条目，完整结果通过 `memory_ref` 取回。成功调用的参数达到 2,000 字符时，后续工具对话保留完成记录及关联结果，参数继续保存在 SQLite。

工作记忆保存目标、约束、重要对象、完成与待办事项。`expected_revision` 检查写入版本，旧版本更新会产生工具错误；之前的工作说明仍可以检索。每次模型请求提供当前可见的工作记忆、实际对象与任务进度，并指出已移除的对象编号。

最近工具对话按字符预算保留，成功的 `compact_context` 会替换此前工具对话。该操作不会清除原始调用、删除图形、提交子 Agent 结果或证明任务完成。原始参数、原始返回、历史工作说明和历史图片仍在 SQLite 中。

`inspect_scene`、`view_canvas`、`search_memory` 与 `recall_memory` 的查询条件及次数按当前内容标识保存。会话压缩后仍会提供最近已查询范围；图形发生变化后，查询属于新的内容状态。重复调用仍有完整记录。

## 错误与恢复

工具错误完整提供给对应 Agent，保留原参数、调用编号与错误内容。若近期对话裁剪或主动压缩移除了尚未发送的错误，下一次模型请求会补充原始工具消息；仅在实际模型响应成功返回后记录已经发送。工具报错后不能在同一轮跳过反馈直接完成任务。

主 Agent 的工作记忆按画布保存，可以用于后续对话。子 Agent 的工作记忆按画布和 `agent_id` 保存，单次运行的调用记录继续使用 `run_id` 关联。关闭、恢复及服务重启继续使用已保存的上下文与检查点，完整旧日志不会在恢复时重新灌入近期对话。

所有记录检查所属画布、Agent 和来源任务。主 Agent 不直接读取子 Agent 的私有工具记录；它通过现有结果摘要审阅子 Agent 工作。当前任务只能检索本次及此前任务，后续排队指令的内容不参与当前决策。删除画布时关联记忆一并删除。

## 可复现检查

```bash
python -m pytest -q tests/test_memory.py --basetemp runs/pytest-memory
python -m scripts.evaluate_memory --database runs/memory-evaluation.sqlite3 --output runs/memory-evaluation.json
```

单元检查使用实际 SQLite 与原生对象，覆盖完整原文和点列取回、超出摘要条目的对象检索、未读错误、重复查询、工作记忆版本、任务顺序与子 Agent 私有上下文恢复。

真实模型检查创建 80 轮对象，要求找到第一轮的“纪念点”、修改颜色与位置、保存工作记忆，再重新打开生产应用继续移动同一对象。报告分别记录模型任务用时、工具使用、原编号及其他 79 个对象的保护、工作记忆持久化和错误反馈。该评测验证长期会话记忆，画面质量仍需根据实际作品单独评价。
