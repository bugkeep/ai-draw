# Agent 记忆与工具压缩

连续绘图需要保留用户目标和对象身份，同时控制每次模型请求中携带的内容。`studio/memory.py` 使用确定性摘要、SQLite 检索及 Agent 主动保存的结构化工作记忆；这些处理不额外请求模型。

## 工具

主 Agent 与子 Agent 均可使用三个工具，各自只能读取本画布及本人范围内的记录。

| 工具 | 主要参数 | 返回与用途 |
| --- | --- | --- |
| `search_memory` | `query`、`object_ids`、`offset`、`limit` | 当前画布或草稿中的对象信息，以及历史调用、对话、工作说明的 `memory_ref` |
| `recall_memory` | `element_id`、`point_offset`、`point_limit` | 当前原生对象属性及一页路径点；返回总点数与下一页位置 |
| `recall_memory` | `memory_ref`、`section`、`offset`、`max_chars` | 已保存摘要，或完整参数、工具返回及工作说明的 JSON 文本页 |
| `compact_context` | `expected_revision`、`goal`、`summary`、`constraints`、`completed`、`pending`、`object_ids`、`evidence_refs` | 保存新的工作记忆版本并压缩此前工具对话 |

检索每页默认八条，最多二十条。原生路径每页默认 128 个点，最多 256 个点；历史原文每页默认 4,000 字符，最多 12,000 字符。返回的下一页位置可以持续使用，分页数量不限制可取回的记录总量或作品规模。

当前对象取回保留原生属性、样式、名称、自定义数据、旋转角度和该页对应的压力值。历史参数或返回保持原始文本；需要恢复完整 JSON 时，应按顺序读取所有页。检索结果与历史说明不能代替当前几何，编辑前应按 `element_id` 取回现有对象。

例如，用户要求修改较早绘制的眼睛，Agent 可以搜索“左眼”，取得编号，再读取当前属性和所需路径点，使用 `reshape_path` 或其他原生工具修改同一对象。需要大量几何计算时，主 Agent 可把目标编号与具体问题交给子 Agent，并审阅其结果摘要后提交。

## 上下文内容

成功工具结果超过 5,000 字符时使用摘要；`inspect_scene` 始终提供摘要。摘要保留对象编号、名称、位置、尺寸、主要样式和点数，较长数组提供数量与部分条目，完整结果通过 `memory_ref` 取回。成功调用的参数达到 2,000 字符时，后续工具对话保留完成记录及关联结果，参数继续保存在 SQLite。

工作记忆保存目标、约束、重要对象、完成与待办事项。`expected_revision` 检查写入版本，旧版本更新会产生工具错误；之前的工作说明仍可以检索。每次模型请求提供当前可见的工作记忆、实际对象与任务进度，并指出已移除的对象编号。

`evidence_refs` 可省略；填写时使用工具实际返回给本 Agent 的 `memory_ref`。网页的 `reference_id` 与绘图的 `result_id` 可以记录在 `summary` 或 `constraints` 中。字段格式与记录归属分别检查，错误指出对应字段或请求的记忆编号，供 Agent 修正后继续保存。

最近工具对话按字符预算保留，成功的 `compact_context` 会替换此前工具对话。该操作不会清除原始调用、删除图形、提交子 Agent 结果或证明任务完成。原始参数、原始返回、历史工作说明和历史图片仍在 SQLite 中。

`inspect_scene`、`view_canvas`、`search_memory` 与 `recall_memory` 的查询条件及次数按当前内容标识保存。会话压缩后仍会提供最近已查询范围；图形发生变化后，查询属于新的内容状态。重复调用仍有完整记录。

准备模型上下文时，运行时会合并同一调用方、同一内容状态下返回相同证据的成功只读调用，只保留最新一组调用与结果。新记录按完整返回计算证据标识，省略默认参数或读取缓存不会制造另一份相同证据；不同分页、对象几何、选择状态和图片编号仍分别保留。合并依据是 SQLite 中实际成功的调用记录，原始日志和历史原文继续可检索。混合批次中的修改操作、工具错误、原始错误参数及未配对消息均保留，绘图次数与请求持续时间不受影响。子 Agent 的检索提示只要求处理本人负责的修改或说明阻碍，不会要求它再派子 Agent。

一页对象具有完全相同的类型或样式属性时，上下文将它们提取到 `scene.element_defaults`；每个 `scene.elements` 条目继承这些属性，自身属性优先。编号、名称、位置、尺寸、点数和分页仍逐项保留。把公共属性与每个条目合并可还原完整摘要，数据库中保存的摘要与原始工具返回继续保持原格式。

子 Agent 获得有效的当前草稿复查后，runtime 可以保存一次读取检查点：将已经实际发送过的成功读取及对应的纯读取推演移出近期对话，保留当前输入、工作记忆、当前图片和复查意见。未读返回、全部工具错误、修改操作及混合批次中的修改说明继续保留；原调用与模型回答仍在 SQLite，可按需检索。`read_checkpoint` 记录已归档数量，不重复添加相同提醒。压缩后的对话和下一条真实模型返回在同一事务中保存，关闭恢复不会重新加入已经归档的读取。

复查明确要求修改时，runtime 还会附上缺陷涉及的当前对象和局部图片，将已经读过的完整工具过程归档为 `repair_checkpoint`。这包含已经送达过的旧错误和修改过程；尚未读到的错误及返回继续完整提供，后续仍可检索旧错误原文。长参数工具的完成摘要与原始工具消息均记录实际发送状态。修正动作保存后再次复查当前图片，检查是否修复目标缺陷及是否产生新损坏。

尚未准备绘图动作时，正常读取与分页不产生草稿完成意见，也不会触发复查检查点；该阶段继续保留规划过程和分页进度。纯研究输入完成时继续使用不增加图片复查请求的路径。

每轮默认对象概览保留最多 12 个已选中或最近使用的对象，并提供全部对象的类型数量和继续检索入口。概览明确标注是否还有其他内容；不在概览中的对象仍然保存在画布上。

`inspect_scene` 返回结构化对象分页，可以组合对象编号、名称文字和画布区域进行过滤。默认每页 12 个对象，可通过 `limit` 选择至多 50 个；`matching_count` 表示全部符合条件的对象数量，沿 `summary.scene.next_page` 可以取回全部匹配对象。每页的准确编号和下一页参数完整保留在上下文中，较长的路径点继续通过 `recall_memory` 按对象检索。分页只控制单次返回大小，不限制对象数量和绘图动作数量。

续页参数携带 `expected_scene_state`。它根据当前画布或子 Agent 私有草稿的实际内容及过滤条件计算；内容或过滤条件发生变化后，旧分页返回明确错误，Agent 需要从 `offset=0` 重新定位。子 Agent 草稿尚未提交时也会检查内容变化。缺失对象错误包含具体编号及重新定位提示。

上下文还提供本次执行的工具累计次数，以及最近修改过的路径编号、名称和修改次数。这些统计在压缩对话和图形变化后保留，供 Agent 检查此前已经尝试的操作，按需取回旧参数，结合当前图片判断剩余问题。统计用于说明历史，不限制绘图次数；它与原始记录使用相同的 Agent 和任务顺序检查。

## 错误与恢复

工具错误完整提供给对应 Agent，保留原参数、调用编号与错误内容。若近期对话裁剪或主动压缩移除了尚未发送的错误，下一次模型请求会补充原始工具消息；仅在实际模型响应成功返回后记录已经发送。工具报错后不能在同一轮跳过反馈直接完成任务。

主 Agent 的工作记忆按画布保存，可以用于后续对话。子 Agent 的工作记忆按画布和 `agent_id` 保存，单次运行的调用记录继续使用 `run_id` 关联。关闭、恢复及服务重启继续使用已保存的上下文与检查点，完整旧日志不会在恢复时重新灌入近期对话。

所有记录检查所属画布、Agent 和来源任务。主 Agent 不直接读取子 Agent 的私有工具记录；它通过现有结果摘要审阅子 Agent 工作。当前任务只能检索本次及此前任务，后续排队指令的内容不参与当前决策。删除画布时关联记忆一并删除。

## 可复现检查

```bash
python -m pytest -q tests/test_memory.py tests/test_scene_inspection.py --basetemp runs/pytest-memory
python -m scripts.evaluate_memory --database runs/memory-evaluation.sqlite3 --output runs/memory-evaluation.json
python -m scripts.evaluate_scene_paging --database runs/scene-paging.sqlite3 --output runs/scene-paging.json
```

如需检查已结束任务中的重复读取，可使用只读续步诊断。它将终态任务数据库备份到一个新数据库，对同一草稿的原始上下文与合并后上下文分别请求一次真实模型，保存输入图片、原始回答、用量和下一步工具选择；不执行返回的工具，也不将结果视为作品验收或任务已恢复。

```bash
python -m scripts.evaluate_read_compaction --source-database runs/archived.sqlite3 --run-id run_example --database runs/read-diagnostic.sqlite3 --output-dir runs/read-diagnostic
```

纠错闭环诊断使用原数据库的只读备份，在新数据库中恢复一条真实的未完成子 Agent 输入，沿用原目标、上下文、私有草稿和模型配置。它记录复查、错误反馈、下一批原生修改及前后 PNG；第一批新增动作保存后或子 Agent 交回结果后停止。该诊断不启动主 Agent，也不将删除错误线条或交回阻碍视为整幅作品完成。

```bash
python -m scripts.evaluate_draft_loop --source-database runs/stalled.sqlite3 --run-id run_example --database runs/loop-diagnostic.sqlite3 --output-dir runs/loop-diagnostic
```

加上 `--until-terminal` 可以继续执行实际修正和后续复查，直到这条子 Agent 输入结束。它仍然不代表主 Agent 已审阅提交，或整幅作品已经通过验收。

单元检查使用实际 SQLite 与原生对象，覆盖完整原文和点列取回、超出摘要条目的对象检索、未读错误、重复查询、工作记忆版本、任务顺序与子 Agent 私有上下文恢复。

真实模型检查创建 80 轮对象，要求找到第一轮的“纪念点”、修改颜色与位置、保存工作记忆，再重新打开生产应用继续移动同一对象。报告分别记录模型任务用时、工具使用、原编号及其他 79 个对象的保护、工作记忆持久化和错误反馈。该评测验证长期会话记忆，画面质量仍需根据实际作品单独评价。

分页评测使用实际模型创建子 Agent，在多页同名笔画中定位唯一红色笔画，由主 Agent 提交对原对象的移动；同时检查其他对象、草稿图片反馈、错误反馈、撤销和重做。

## 读取密集路径

`recall_memory` 默认 `point_tolerance=0`，继续逐点返回当前原始几何。查看一条密集曲线的整体形状时，可设置 `point_tolerance=1`，在 1 个画布单位的误差范围内选择较少的原始采样点。它只改变读取结果，画布、压力数据和撤销历史都不会改写。返回的 `source_point_count` 是原采样数，`point_count` 是本次序列总数，`source_point_indices` 将读取点映射回原路径，`geometry_exact` 明确区分精确和简化读取。

下一页直接使用返回的 `next_page`。其中的 `expected_path_state` 绑定当前对象内容及简化参数；读取过程中对象或参数发生变化时，旧页请求会被拒绝，应从 `point_offset=0` 重新读取。分页数量不限制整幅画或单条路径的总采样数。成功读取同一状态下的相同内容会显示重复次数，提示按需要翻页、使用简化几何或完成实际修改；不会因此停止 Agent 或限制工具调用次数。
