# Draw Agent Studio 架构

## 职责

| 组件 | 输入 | 输出与职责 |
| --- | --- | --- |
| Excalidraw 编辑器 | 用户手势、画布事件 | 原生对象、选择状态和逐帧画笔展示 |
| 会话 API | 对话文本、画布快照 | 会话、任务、版本化画布和事件连接 |
| 模型配置与请求 | 设置表单、服务端凭据 | 单一共享连接、多厂商 API 适配、连接测试与加密保存 |
| 主 Agent | 最近对话、当前共享画布图片与摘要、用户目标 | 构图、简单几何与语义编辑、描线计划、子 Agent 生命周期和结果审阅提交 |
| 子 Agent | 独立输入队列、私有草稿图片、相关对象与绘图工具 | 手工笔画与曲线几何、可恢复的私有上下文、绘图结果与结构化摘要 |
| 图片服务 | 当前原生对象、可选检查区域 | 复用 Chromium 的 Excalidraw 原生 PNG 导出、坐标映射和 SQLite 图片记录 |
| 结果预览服务 | 当前共享画布、待提交结果及依赖 | 预先校验全部动作并生成候选 PNG，记录主 Agent 是否已收到该结果的图片 |
| 绘图执行器 | 主 Agent 接受的动作 | 按顺序提交、对象版本检查、事件与撤销记录 |
| 资料检索工具 | 具体绘图问题、主题与关注词 | 免费公共搜索、正文读取、相关步骤及来源编号 |
| 参考图片服务 | 公共插图来源、源像素区域及共同画布范围 | SQLite 图片存储、所属 Agent 的当前参考图、提取轮廓与原生画笔映射 |
| 记忆服务 | 完整工具记录、结构化工作说明、检索条件 | 成功结果摘要、分页精确取回、独立工作记忆与未读错误反馈 |
| SQLite | 文档、对话、任务和工具记录 | 重启恢复及事件追溯 |

主 Agent 通过 `spawn_agent`、`send_input`、`wait_agent`、`close_agent` 和 `resume_agent` 管理子 Agent。`agent_id` 标识可复用会话，每条输入具有独立 `input_id` 和 `run_id`。单个 Agent 顺序处理输入，不同 Agent 并发准备。每个子 Agent 使用私有画布，调用原生绘图工具；工具列表和 runtime 校验均禁止子 Agent 创建或控制其他 Agent。

手工笔画的角色边界同时作用于模型工具定义与运行时校验：主 Agent 不接收 `draw_paths`、`reshape_path`，其创建工具也不接受 `freedraw`；通过 `update_elements.points` 绕过曲线工具同样会被拒绝。此类任务通过原生生命周期工具交给绘图子 Agent。主 Agent 保留简单形状、文字、连接线、选择、移动、样式与擦除，以及参数简短的确定性参考描线计划。几何长参数留在子 Agent 的私有记录中，主 Agent 处理摘要、图片和提交决定，不设置总笔画数或调用次数上限。

角色规则集中在 `studio/prompts.py`：主 Agent 负责当前作画阶段、统一映射和组合审阅，子 Agent 每条输入交付一个可以局部审阅的结果，再复用同一身份接受后续部位或修正。参数语法与默认值保留在工具 schema，避免在系统提示中重复整份工具说明。发给模型的 schema 省略展示用 `title` 注解，保留字段、枚举、必填条件、边界、引用和字面默认值；运行时仍使用完整 Pydantic 校验。

主 Agent 接收状态、摘要、动作数量和 `result_id`，通过 `apply_agent_result` 接受并提交结果，通过 `reject_agent_result` 记录拒绝原因。完整动作、画笔点列、私有上下文和调用记录保存在 SQLite。主 Agent 可以提交先完成的部分，其余 Agent 继续执行。工具返回通过 `call_id` 关联，重复调用读取已有返回；共享画布修改和提交进度在同一事务中保存。对同一对象的并发修改通过对象内容检查拒绝覆盖。

`AgentResultReview` 在主 Agent 请求模型前自动重放一份可提交结果，将候选图加入独立的图片消息。重放只作用于当前共享画布的副本，不替换为较早的私有草稿。所有目标的内容检查及依赖检查通过后才生成图片；主 Agent 收到候选全图后才能提交。`view_agent_result` 支持选择其他候选和放大区域。预览、当前共享画布与私有草稿的记录分别标记；原生创建动作使用对象编号生成稳定的绘制 seed，使预览与实际提交的手绘外观一致。

绘图动作和模型请求不设置数量或执行期限。批量绘图工具在应用到私有画布前校验全部参数。关闭子 Agent 保留工具检查点与输入队列，恢复使用原身份继续未完成工作；等待工具只负责观察。主 Agent、子 Agent 共用本次任务开始时的模型及 API Key。OpenAI 兼容的 Chat Completions 请求使用 OpenAI 官方异步 SDK；其余厂商及 Responses 请求由 LiteLLM 适配。客户端复用 HTTP 连接，并在服务结束时关闭。状态转换、工具参数和恢复方式见[子 Agent 生命周期](agent-lifecycle.md)。

同一事件循环内，使用相同厂商路由、地址、凭据和 API 模式的请求共用连接恢复队列。HTTP 429 更新共同等待时间，后续请求按到达顺序取得发送机会；正常阶段支持并发。厂商 `Retry-After` 与指数等待均参与恢复，连续成功后恢复正常并发。排队等待、发送请求和重试状态通过所属任务的画布事件展示，完整厂商错误只写入 SQLite。

`draw_paths` 将有名称的关键点曲线转换为原生画笔对象，支持统一坐标原点、缩放、逐笔样式和闭合填色轮廓。前景可用实心填色遮住背景，仍保存为原生画笔对象。`reshape_path` 替换已有路径几何，保留对象编号和样式，默认维持已有填色路径的闭合状态。`reorder_elements` 在不改变几何的情况下调整对象前后关系，保持各组内部顺序并跳过锁定目标。`inspect_scene` 根据对象编号、名称或区域查询；模型上下文中的长结果经过摘要处理，完整几何由 `recall_memory` 按对象分页取回。所有修改使用同一个版本检查、提交、撤销与重做流程。

`erase_strokes` 以绝对画布坐标擦除整条对象或画笔的局部线段。局部几何由 Shapely 处理，剩余部分继续使用原生对象，旋转与压力数据一并处理。未指定目标的空间擦除按层级扣除实心不透明前景的遮挡区域；局部擦除保留填色轮廓，明确的对象编号允许定向修改隐藏目标。子 Agent 准备动作时记录实际目标、可见区域保护和内容指纹，提交时维持同一擦除语义，并保留其他 Agent 后续增加的笔画。

模型请求前，`CanvasVision` 根据对象内容与顺序生成内容标识，复用相同任务、调用者与区域的图片。`CanvasRenderer` 延迟启动并复用 Node.js、Chromium 与独立 `render.html`，通过 Excalidraw 导出器生成实际图片。全图与所需局部图片以图片消息附在当前上下文，历史图片保存在 `canvas_observations`。成功返回模型响应后记录图片已经发送，完成时核查该调用者已收到当前内容的全图。主 Agent 和各子 Agent 的检查状态分别保存。

主 Agent 的模型绘图任务保存本轮开始时的画布，完成时进行独立图片检查。提交过子 Agent 的修改，且本任务已无运行子 Agent 和待处理结果时，也会在下一次主 Agent 请求前执行阶段检查；刚发生工具错误时先把错误交给主 Agent。检查器与主 Agent 使用同一模型连接和限流恢复队列，使用独立上下文，先只描述实际图片，再根据当前用户要求、开始与当前画布和有限的坐标变化摘要检查任务匹配、比例连接、必要细节、线条及构图。子 Agent 的长工具记录不进入检查器。新作品检查整体表达，局部修改只检查本轮要求及新增损坏；主 Agent 的普通文字结束与 `finish_drawing` 均经过这一流程。确定性快捷绘图与撤销重做继续走原有执行分支。

与当前画布匹配的评语单独附在压缩后的主 Agent 上下文，明确列出缺陷或完成条件，不混入历史检查。改动几何、层级、选择或模型配置后，旧评语不再作为当前检查。阶段检查不自动结束任务；主 Agent 仍需收到实际当前图片并处理全部工具错误、子 Agent 与结果。当前画面已经通过时，完成流程复用该记录，避免再发一组检查请求。`model_context.quality_review_keys` 记录哪些当前评语实际进入了模型请求。

适用项目未通过、检查响应格式无效或检查期间画布改变时，任务不能由该次检查宣布完成。缺陷及修正建议作为完整错误返回主 Agent；无效模型原文同时保留在错误中。已完成检查按任务、画布内容、选择状态、初始画布、模型配置和检查规则缓存，同一画面不重复发起模型检查。原始响应、初始文档与图片继续保存在 SQLite。这个检查是防止错误完成的机制，复杂作品能否稳定修正并达到用户要求仍需完整作画评测。

图片日志只包含编号、范围和耗时；原始 PNG 不写入工具对话。成功工具的长参数和长返回保存在 SQLite，上下文提供摘要、对象编号及检索编号。工具错误保留完整参数、原 `call_id` 与返回；尚未发送给模型的错误在会话压缩后重新加入下一轮，收到实际模型响应后才记录为已发送。子 Agent 擦除已有参考对象后，上下文提供其已移除状态与当前草稿，不要求已经移除的对象继续存在。

`AgentMemory` 为主 Agent 与每个子 Agent 分别保存工作记忆。`compact_context` 使用版本校验更新目标、约束、对象索引、已完成及待办事项，成功后清理此前工具对话；当前工作记忆与实际画布、任务进度一起组成后续上下文。`search_memory` 查找当前对象和历史记录，`recall_memory` 分页读取当前原生属性与点列，或者已保存的调用参数及原文。历史记录明确标注来源任务，不作为当前几何的依据。

原始调用使用 `agent_tool_calls` 保存，`agent_memories` 保存摘要、检索内容、来源与发送状态，`agent_working_memory` 保存每个 Agent 的当前版本指针。主 Agent 的工作记忆可以用于同一画布的后续任务；子 Agent 的记忆随原 `agent_id` 保留，并在关闭恢复时继续使用。检索检查画布、Agent 和任务顺序，后续排队任务的消息与记忆不会进入当前任务。重复查询按当前内容标识记录，压缩会话后仍可知道已经读取的范围。完整说明见[Agent 记忆与工具压缩](agent-memory.md)。

对象内容检查使用 RFC 8785 的规范 JSON 表示。浏览器对整数、小数以及空绑定列表的等价表示不会导致冲突或新增撤销记录；数据库已有的内容指纹仍按其原格式验证。画布对象数量和整体内容长度不设置应用层上限，长期绘图的资源需求由实际作品决定。

画布修改、对应的撤销历史、子 Agent 提交进度和 `scene_patch` 事件在同一 SQLite 写入事务中保存；事件写入失败时全部回滚。事件包含基础版本、新版本、变更的原生对象、移除编号与选择状态；只有图层顺序实际变化时才附带顺序列表。普通新增和移动不重复发送其他对象。会话读取使用同一 SQLite 读快照，避免文档版本与事件游标错开。

新编辑器使用 `/documents/{id}/events?after=SEQ&patches=true`，从已收到的事件编号继续；服务端按数据库顺序回放，再接收实时通知。客户端忽略旧版本，遇到缺失的画布版本时缓存后续增量并重新读取会话快照，然后继续应用尚未包含的增量。未声明 `patches=true` 的旧客户端仍收到 `scene` 快照，转换时使用最新画布，历史逐步回放应使用增量协议。编辑器收到的原生对象使用独立副本，自动补充的版本、索引等元数据不作为新的手工绘图保存。

API 7 的手动编辑使用 `ManualEdits` 保存待提交与正在发送的两批操作，不将本地草稿写进代表服务器状态的文档引用。每次收到新文档时，页面在其上展示尚未确认的本地变更；发送中的请求保持原操作编号和参数，后续手势排在下一批。后端按字段合并不相交的修改，将路径位置、角度、尺寸与采样点作为一组检查，避免移动旧轮廓时混入新轮廓。删除、对象类型及图层冲突也经过检查。同一内容冲突返回当前文档和冲突编号，前端保留草稿供用户选择；正常网络失败保留操作供重试。这里的草稿保存在当前页面内存中，尚未实现离线草稿跨刷新恢复。

`manual_edit_receipts` 以文档、浏览器身份和操作编号为键，保存请求哈希及已提交版本。对象修改、撤销历史、收据和增量事件在同一事务中完成；丢失响应后的相同请求返回已提交状态与当前文档，不再次执行。收据只保存哈希而不复制完整点列。旧 `PUT scene` 接口保留严格版本检查，旧客户端不能用过期整图覆盖新内容。

`StrokeScene` 将完整的显示文档复制成独立编辑器对象，后续过程帧复用该批副本，只复制新增的笔画。正式文档更新或取消恢复时重新建立副本，不复用中断的临时笔画。接收更新前会收集尚未回调的实际手动编辑；程序更新后的延迟回调重新读取当前编辑器状态，避免把过期过程帧存入文档或丢弃更新间隙中的用户操作。

`search_references` 使用 DDGS 公共搜索和网页正文筛选，`read_reference` 从已验证来源中按关注词选择片段。原始结果、全文和筛选记录保存在 SQLite，短片段和来源编号返回调用者。研究子 Agent 与绘图子 Agent 使用相同生命周期，研究工作可以不产生动作。主 Agent 审核研究摘要，再决定绘图内容。具体限制和公共搜索配置见[绘图工具与资料检索](drawing-tools.md)。

`ReferenceImages` 独立保存原始参考图片、解码像素、当前查看记录和完整轮廓路径。搜索及参考图片按画布与来源任务顺序读取，后续排队任务的图片不参与当前任务。图片选择与已发送记录按主 Agent 调用者或子 Agent 的 `run_id` 分开保存，模型上下文明确区分参考图与实际画布。提取轮廓前检查该调用者已收到完整源图。

区域轮廓使用 scikit-image、Skan 和 Shapely 生成有序原生笔画，图像解码、页面提取与轮廓计算在线程中进行；共享画布与数据库提交仍由原 runtime 负责。所有区域通过整张源图的共同 `target` 保持比例与位置。子 Agent 准备私有动作，主 Agent 审阅结果后逐笔提交，沿用版本检查、过程事件和撤销重做；主 Agent 上下文只接收编号、名称、统计和结果摘要。

主 Agent 与子 Agent 均可把 `finish_drawing` 放在本轮最后一个工具位置，传入完成说明。runtime 先处理前面的全部工具，任何错误都会以原 `call_id` 返回上下文并拒绝本轮完成信号。主 Agent 还需要处理所有运行子 Agent 与待提交结果。成功时直接结束本轮，省去仅生成完成文本的模型请求。

画布由服务端保存。Excalidraw 的手动修改携带文档版本提交；版本变化时接口返回 HTTP 409，前端重新读取画布。绘图执行器每提交一步就发出 `scene` 事件。画笔对象在提交前发出多个 `stroke_progress` 事件，前端用临时对象显示轨迹，最后由正式 `scene` 事件替换。WebSocket 重连时带上最后收到的事件编号，从 SQLite 读取遗漏事件。

画笔展示根据路径长度安排过程帧和等待时间。每条路径仍按原顺序显示并独立提交，过程事件和正式结果均保存到 SQLite；前端刷新可以继续读取当前任务阶段和已有作品。

撤销与重做由 SQLite 保存最近 50 次内容修改。历史数组使用 SQLite 原生 JSON 函数更新，Python 只解码当前画布和本次撤销或重做的目标，保存格式保持为原有 JSON 文本。画布、历史和子 Agent 提交进度在同一事务中保存，更新失败时一并保持原状态。常见明确指令由 `studio/fast_path.py` 准备动作并经过同一个绘图执行器。

复杂新作品按构图与轮廓、主要特征、具体修正等绘图阶段安排输入。每条子 Agent 输入说明本阶段的区域、共同坐标、部位连接位置与可见完成条件。主 Agent 及时提交已准备的阶段结果，查看组合后的实际画面，通过 `send_input` 复用原 Agent 继续后续阶段。整体目标和剩余工作保存在工作记忆中；单个阶段完成后仍须继续完成用户要求的整幅作品。

独立审图报告仍经过严格 schema 校验。格式错误完整返回主 Agent，并单独保存在 SQLite。下次审阅同一任务、相同画面和模型配置时，审图模型收到自己上次的原始报告及校验错误；已经取得的同一画面盲看描述可以复用。画布、选择、模型配置或任务改变后不复用这些反馈。格式恢复不修改作品，也不会把无效报告或额外字段当成审图通过。

每个会话关联独立文档，文档拥有自己的执行锁、事件订阅和历史记录。同一画布内的任务按顺序执行；构建 Agent 上下文时按任务创建顺序读取本次及此前任务的消息，排除后续排队指令。不同画布可以同时执行。前端切换会话时关闭旧连接、清理待保存快照，并使用会话加载编号与文档 ID 校验异步返回及编辑器回调。读取会话时同时返回事件编号，实时连接从该编号继续读取。

模型设置保存在 SQLite，加密文件单独保存在服务端。已有保存配置优先于可选 `.env` 初始配置。读取设置仅返回 API Key 是否存在。设置页每秒查询全局任务状态；任何任务运行或排队时禁止保存，后端在同步写入前再次检查。配置版本用于拒绝其他页面覆盖已更新的设置。

## API

模型检查图的 `observation_id` 也可以作为 `draw_paths`、`reshape_path`、`erase_strokes` 的图片坐标来源。`CanvasVision.ground_tool` 检查任务、调用者、已发送状态及当前内容哈希，然后换算到画布。`coordinate_space=image_normalized` 使用两轴 `0..1000` 与实际 `scene_bounds`；默认的像素模式继续使用 PNG 的逐方向比例。准备后的动作与事务仍只使用画布单位，工具完整记录保留原始坐标模式、参数和映射依据。提交幂等在坐标换算之前返回已有调用结果，避免重试时重复执行。

`canvas_viewports` 按任务与调用者保存指定局部区域，随任务级联删除。每次上下文重新渲染当前区域，复用相同内容的图片缓存；自动提供最新局部图而非旧版本图片。局部模型图片通过 `image_guide` 加入像素刻度，保存的 PNG、内容哈希与原生画布不受辅助层影响。主 Agent 的待提交结果检查仍使用独立调用者编号及原始预览。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/studio/health` | 服务、API 版本和模型配置状态 |
| `GET /api/studio/settings` | 读取公开配置、厂商列表及全局任务状态 |
| `PUT /api/studio/settings` | 校验配置版本并加密保存；绘图期间返回 HTTP 409 |
| `POST /api/studio/settings/test` | 使用随机图形图片验证图片识别、文本与工具调用能力 |
| `GET/POST /api/studio/sessions` | 列出与创建会话 |
| `GET /api/studio/sessions/{id}` | 读取会话、对话、画布和任务 |
| `GET /api/studio/sessions/{id}/agents` | 读取该画布的子 Agent 状态及结果摘要 |
| `GET /api/studio/sessions/{id}/agents/{agent_id}` | 读取指定子 Agent，检查画布归属 |
| `GET /api/studio/sessions/{id}/observations/{observation_id}` | 读取属于该画布的 PNG 检查图片 |
| `GET /api/studio/sessions/{id}/reference-images/{reference_id}` | 读取属于该画布的已保存参考 PNG |
| `PATCH /api/studio/sessions/{id}` | 修改会话与关联画布名称，保留图形、对话、任务和撤销历史 |
| `DELETE /api/studio/sessions/{id}` | 删除该会话及其画布、消息、任务、日志和事件；有运行或排队任务时返回 HTTP 409 |
| `POST /api/studio/sessions/{id}/messages` | 排队执行一条绘图指令 |
| `PUT /api/studio/documents/{id}/scene` | 兼容整图保存，严格检查版本 |
| `PATCH /api/studio/documents/{id}/scene` | 按对象保存手动修改，自动合并不冲突字段，返回冲突或幂等收据 |
| `POST /api/studio/documents/{id}/history` | 撤销或重做 |
| `GET /api/studio/tasks/{id}` | 查询任务状态和耗时 |
| `POST /api/studio/tasks/{id}/cancel` | 停止任务 |
| `GET /api/studio/tasks/{id}/logs` | 查看 SQLite 工具记录 |
| `WS /api/studio/documents/{id}/events?after=N` | 接收画布、任务、对话和画笔事件 |

`runs/studio.sqlite3` 包含用户对话及完整工具记录，应按应用数据保护。运行评测时 `runs/` 也保存结果文件。

名称修改通过独立的 `session` 事件通知当前画布的窗口，不增加绘图版本或撤销记录。会话列表与对话区域各自限制高度并处理滚动，编辑器使用窗口剩余空间。

删除在一个 SQLite 事务中移除关联数据，提交成功后向该文档的订阅者发送 `session_deleted` 通知并关闭连接。前端清理旧画布的待保存内容与事件连接，打开其他会话；列表为空时创建空白画布。断开期间错过通知的窗口会在重连时检查会话是否存在。名称保存与删除只作用于指定会话。
